# PAD 前端规范 v1

> 2026-11-04 · 适用：PAD（WPF）所有页面、弹窗、CLI 的人类可读输出。本文是硬规则；新增 UI 前先查本规范，PR 走第 9 节检查清单。
> 视觉手册（可打开）：[`agent-pack-dsh/docs/frontend-spec/index.html`](index.html)；截图见 `EVIDENCE/D107-install-concept/spec/`。

## 0. 五条硬原则

1. **能删就删**：去不去掉没有任何区别的文字，直接删。
2. **有用但吵 → 藏起来，别摆出来**：用层级/悬停/展开/详情承载，常驻界面只留"此刻要决定的那一句"。
3. **视觉即语义**：图标、颜色、状态、动效优先；句子是最后手段。一个好的界面，不读字也能看懂。
4. **一次只让人看一件事**：一个视口/弹窗只允许一个主信息层级；禁止一屏堆字。
5. **顺手 > 好看 > 少点击**：默认值合理、动作就近、键盘可用；同类概念必须同一套设计，禁止自创（尤其禁止用大字/长文字当图标）。

## 1. 文字纪律（Text Discipline）

### 1.1 决策树（每段文字都过一遍）

```
这段字删掉，用户会做错事吗？
├─ 不会 → 删
└─ 会 → 它是哪种？
   ├─ 状态/结果（能不能装/成功没） → 做成药丸/颜色/统计块（视觉）
   ├─ 操作说明（点哪个按钮）      → 写进按钮文案或 Tooltip（短）
   └─ 技术细节（包名/版本/报错原文）→ 折叠「详情」/Tooltip/报告里（按需展开）
```

### 1.2 常驻限制

- 一个视区 **最多 1 句主提示**；行内辅助信息 **≤1 行**（超出省略号 + Tooltip）。
- 弹窗正文：**≤1 段短说明 + 视觉化清单**；技术原文进「展开详情」。
- 统计用 **数字块**，不用句子（"新增 9 / 豁免 1 / 跳过 1" 而不是一段话）。
- 状态词固定 2–4 字：`可装 / 需授权 / 已下架 / 已启用 / 已停用 / 不完整 / 未登记`。
- 动作词固定动词：`安装 / 修复 / 停用 / 启用 / 卸载 / 导出 / 新建实例`，不混用同义词。

### 1.3 反例（本轮真实问题）

- ❌ 预检弹窗把 `peerDependencies: @deepseek-ai/dsh-commands ^0.1.0-rc.6 …` 铺在正文里 → ✅ 行内只写「`dsh-find-skill@0.2.1` 与内核不兼容 · 需授权」，原文放「展开详情」。
- ❌ 版本页曾经用「已装到 sisyphus · 已建实例 X」文字表达装态 → ✅ 删掉，装态回到实例页（发光 + 账本药丸）。
- ❌ 用字符「包」当图标 pill → ✅ 统一用包图标；无图标时用同尺寸 fallback 图标，不用文字。
- ❌ 「本机包库 3 个」这类计数当正文 → ✅ 计数放列表头/搜索框右侧弱化位置，或直接不显示。

## 2. 视觉表达（Visual-first）

优先顺序：**图标 > 颜色/状态 > 药丸 > 短标签 > 句子**。

| 含义 | 颜色 | 图标（统一） | 常见形态 |
|---|---|---|---|
| 可装 / 已启用 / 运行中 | green `#3fbf73` | ✓ / ● | 药丸「可装」、呼吸光 |
| 需注意 / 需授权 / 不完整 | amber `#c9932f` | ! / ◐ | 药丸「需授权」「不完整」 |
| 不可 / 失败 / 缺失 | red `#c24a4a` | ✕ / ⛔ | 药丸「已下架」 |
| 停用 / 未登记 / 中性 | grey `#8b989f` | ○ / ⏸ | 药丸、降透明度 |

规则：
- 同一个含义在全局只用 **一个** icon + 一个颜色；不允许这页用 ✓、那页用 ●。
- 图标只从第 7 节图标表取；新增图标必须先进表 + 改规范。
- 禁止文字作图：不得用大写字母、长单词、汉字块当图标（「包」pill 这类过渡形态要替换）。
- 发光/呼吸只有一个语义：**启用中/运行中**；不要拿它当装饰。

## 3. 顺手（Interaction Efficiency）

- **默认值**：装包默认目标 = 当前实例；菜单第一项 = 最常用动作；危险操作才确认，其余直接执行。
- **就近**：动作放在对象行；同一类动作在所有列表里的位置一致（主按钮在行右）。
- **少层级**：列表能直接完成的不绕弹窗；必须弹窗时一屏内完成（不要"下一步→下一步"）。
- **键盘**：Enter = 主操作，Esc = 取消，`--shot` 等 CLI 参数与 UI 语义对齐。
- **记忆**：上次实例/profile/窗口大小/筛选；刷新不丢上下文。
- **可取消**：任何超过 2s 的操作都有取消途径或明确进度阶段。

## 4. 动感与反馈（Motion & Feedback）

| 场景 | 时长/曲线 | 备注 |
|---|---|---|
| hover / focus | 120ms ease-out | 颜色/边框/背景变化 |
| 状态切换（启用/停用/装态） | 160–200ms ease-out | 不弹跳 |
| 菜单/弹窗出现 | 180ms ease-out + 8px 上移 | 淡入 |
| 呼吸/发光（运行中/启用中） | 1.6s AutoReverse 循环 | 全局唯一"活着"语义 |
| 列表行插入/删除 | 160ms 高度/透明度 | 避免整页闪烁 |

- **每个操作必须有反馈**：按下态 → 进度（>400ms 才显示，避免闪）→ 成功 Toast/行内状态 → 失败原样错误 + 重试入口。**禁止静默**。
- 长任务显示阶段：`预检 → 授权 → 安装 → 报告`（同一窗口内推进，不新开窗口）。
- 反馈位置：能就地就在行内变，全局 Toast 只做结果摘要；错误必须可读、可复制、可重试。

## 5. 一致性（Consistency）

- **一套图标**（第 7 节表，目标 ≤20 个）；同一概念全局一个。
- **一套组件尺寸**：按钮 34/40 高、行 64/76 高、药丸 24 高、圆角统一 token。
- **一套文案句式**：动作动词、状态词、标点风格统一；中英文之间加空格；按钮文案 2–4 字。
- **禁止自创**：新颜色/新组件/新图标先查表；需要新增时先改规范（本文档 + 视觉手册）再实现。
- 同一组件只能有一种形态：不允许"这里胶囊、那里方角"；不允许一页两种行高。

## 6. Design Tokens

**颜色**：`bg #eef1f4` · `card #ffffff` · `line #e3e7ec` · `ink #1c2529` · `ink-2 #55646c` · `muted #8b989f` · `accent #0f5f6b`（hover `#14707e`）· `accent-wash #e6f1f3` · `green #3fbf73 / text #1e7b46 / wash #e8f6ee` · `amber #c9932f / #8a6416 / #fbf1de` · `red #c24a4a / #a53c3c / #fbeaea`。

**字号**：22 页/卡标题 · 19 行标题 · 17 正文/按钮 · 15 辅助 · 13 说明/Tooltip；行高 1.4–1.5。禁止正文 <15。

**间距**：4 / 8 / 12 / 16 / 24 / 32 / 40；卡片 padding 22–24；列表行内 gap 12–16。

**圆角**：控件 10 · 行 14 · 卡片 16 · 弹窗 20 · 药丸 999。

**阴影**：card `0 1px 2px rgba(16,24,32,.04), 0 8px 24px rgba(16,24,32,.05)`；pop `0 12px 40px rgba(16,24,32,.18)`；dialog `0 30px 80px rgba(10,20,25,.35)`。

**动效**：见第 4 节表。

## 7. 组件规范

### 7.1 列表行（Pack/Instance/Plugin）
- 结构：`[图标 26/30] [标题 + 版本] [辅助一行] [状态药丸] …… [主按钮]`。
- 辅助行 ≤1 行（内核 · 插件数 · 相对路径），超出省略 + Tooltip。
- 主按钮在行右；次动作（修复/卸载）放行内 icon 按钮或菜单；**不要每行放三个大按钮**。
- 已启用行发光（见 2.4）；停用行降透明度 0.85，不发光。

### 7.2 药丸（Pill）
- 高度 24、左右 padding 10、圆角 999、13–14 号字；同时最多 3 个，超过折叠成「+N」。
- 绿色=可/已启用；琥珀=需注意；红色=不可/失败；灰色=中性/停用。

### 7.3 按钮
- 主按钮：accent 底白字；次按钮：白底描边；行内动作：icon 按钮或 15 号小按钮。
- 文案动词 2–4 字；带菜单的按钮加 `▾`；禁用态降透明度 + Tooltip 说明原因。
- 一次操作的按钮之间不重复同义（例如"开始安装"和"安装"不要同时出现）。

### 7.4 弹窗
- 结构：标题（名词）+ 一句副标题（为什么在这）+ 视觉清单 + 底部 2–3 个动作。
- 宽度 640–1020；内容超过一屏才滚动；技术细节折叠进「展开详情」。
- 危险操作确认文案写后果，不写"确定吗？"。

### 7.5 空态 / 加载 / 错误 / Toast
- 空态：一句"还没有 X" + 一个主按钮；不要放解释长文。
- 加载：骨架行（≤3）+ 阶段文案；超过 400ms 才显示。
- 错误：一行摘要 + 「展开详情」原文 + 重试；不要只弹一个红字。
- Toast：一句话结果（成功=绿、失败=红），3–5s 自动消失；详情进日志/报告。

## 8. 标准模式（Before → After）

### 8.1 安装前检查（本轮新增窗口）
- **Before（当前）**：8 段正文 + 技术原文 + 两条复选说明，一屏字。
- **After**：4 行视觉清单（内核 ✓ / 插件 10 个 = 8 绿 + 1 琥珀 + 1 红 / 冲突无 / 管理器自动补）+ 一行"要你决定：接受 1 个风险、跳过 1 个下架" + 两个勾选 + 「开始安装」；每行点「详情」才展开 peer 原文。
- 见视觉手册 `index.html` 的 before/after 示例。

### 8.2 版本页包行
- Before：只有「新建实例」+ 装态文字。After：「安装 ▾」（装到当前实例 / 新建实例 / 先检查），装态不写文字（D106/D107 已实现）。

### 8.3 安装报告
- Before：一段话。After：状态药丸 + 5 个数字块 + 每类可展开逐条；按钮 3 个以内。

## 9. PR 检查清单（每条都要过）

1. 常驻文字删到 ≤1 句主提示 / ≤1 行辅助？
2. 技术原文都进了 Tooltip/展开/报告？
3. 状态是否用药丸/颜色/图标，而不是句子？
4. 图标都来自第 7 节表，没有文字作图？
5. 同类组件/尺寸/圆角/状态色与其他页面一致？
6. 默认值顺手吗（目标实例、菜单第一项、键盘 Enter/Esc）？
7. 每个操作有反馈吗（按下/进度/成功/失败/可重试）？
8. 动效时长符合第 4 节，且没有第二个"呼吸"语义？
9. 一屏是否只让人看一件事？堆字了吗？
10. 文案动词/状态词与全局一致，没有同义词混用？

## 10. 迁移清单（按优先级）

1. `PackPreflightWindow`：技术原文收进「详情」；检查行改视觉化（8 段文字 → 4 行）。
2. `PackPickerWindow`：行辅助行收敛到一行；计数弱化。
3. `VersionsView` / `InstanceView`：确认没有残留长句说明；所有状态用统一药丸。
4. 全局：把「包」文字 pill fallback 换成统一包图标；检查是否还有文字当图标的地方。
5. 建立 `Icons.xaml` 单一图标源 + `Tokens.xaml` 单一 token 源（目前样式散在 Theme/Controls）。
