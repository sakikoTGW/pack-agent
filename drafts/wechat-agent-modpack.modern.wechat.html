我做了个 Agent 整合包：一份 .pack.json，装进 Claude Code / Codex

Agent Modpack · @sakikotgw/pack-agent

换电脑、换 Claude Code 到 Codex，skills 和 MCP 常常散掉。同事丢三个 skill 文件夹过来，还得自己猜 rule 写哪、装完怎么卸。

OpenSkills 一类工具解决的是「装一份 SKILL.md」。还有一堆工具做「本机一份源配置，symlink 到所有 agent」。

我要的是第三种：把整个角色打成能甩给别人的包——skills、rules、MCP、经验罐头一起走，能看清单，能按账本卸干净。

于是开源了 Agent Modpack（CLI：packagent）。


最快试一把

有人甩给你一个 foo.pack.json（要 Node、网络、Bun）：

npx --yes -p @sakikotgw/pack-agent packagent install foo.pack.json

跟任意 coding agent 说「装一下这个」——用上面这条。

Windows 上别用旧写法 npx --package … -- pack-agent，会报「不是内部或外部命令」。

长期用：

npm install @sakikotgw/pack-agent
packagent detect
packagent install foo.pack.json --runtime claude-code

自己打包装角色

packagent agents init
packagent export --agent <角色名>
packagent show .agent-pack/exports/<角色名>.pack.json
packagent install .agent-pack/exports/<角色名>.pack.json
packagent eject --name <角色名>

角色写在 .agent-pack/agents.yaml。不带 --agent 直接 export 会被硬拒绝——一个包只封一个角色。

detect 看本机有哪些 harness。默认对能装的各投一份；只想 Claude Code 就加 --runtime claude-code。


装成功了，上下文却是空的

Hermes 上我踩过一脚：hook 写进配置了，install 也报成功，下一轮对话里经验罐头是空的。

Hermes 的 pre_llm_call 只认 stdout 里的 {&quot;context&quot;:&quot;...&quot;}。当时脚本吐的是 Claude 那套 hookSpecificOutput。用 Hermes 自己的解析函数喂进去，结果是 None——不是报错，是静默当没发生。

改成正确形状之后，同样的 marker 才能进 context。

这件事把产品钉死了：装的是角色拼进模型前的那截输入，不是「磁盘上多了几个文件夹」。

看报告里的 skipped 和 notes，别只看 ok: true。OpenClaw / Hermes 的全局扫描目录默认不写，要显式 --global-config。早期无条件写全局，临时目录会在 ~/.hermes 攒死路径。

经验罐头默认不当 skill——走 SessionStart / pre_llm_call 注入，避免污染技能检索。缺瓶口录制的包标 L1，换模型会漂。


它不做什么

  • 不是 skill 商店，不去发现十几万个 skill
  • 不是「一份源目录永远 symlink」的同步器
  • 默认不碰全局配置；Cursor 的 skill 投射会跳过，但仍可能写项目级 .cursor/mcp.json 挂上 MCP

心智上可以记一句：Harness 像启动器，.pack.json 像整合包清单。CLI 就是启动器。
